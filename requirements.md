# Voice Quiz App — Requirements (v1)

## Overview
A web-based study tool that quizzes the user using text-to-speech, accepts
spoken answers via speech-to-text, and uses an LLM to judge correctness.
Designed to work across any course or project.

---

## Architecture
- **Frontend:** Single-page HTML/JS (no framework for v1)
- **Backend:** Python FastAPI server
- **AI:** Claude API (grading + question generation)
- **Browser target:** Chrome (primary target for Web Speech API)

---

## Functional Requirements

### Question Generation
- FR-1: User uploads a study file (PDF or .docx) through the web UI
- FR-2: Backend extracts text from the uploaded file
  - PDF: PyMuPDF (`fitz`)
  - DOCX: `python-docx`
- FR-3: Extracted text is sent to the Claude API with a prompt to generate quiz questions
- FR-4: Claude returns questions as structured JSON matching the question bank format
- FR-5: Generated questions are sent to the frontend to begin the quiz session
- FR-6: The system generates 10 questions by default (or fewer if the source material is too short)

### Question Delivery
- FR-7: App reads each question aloud using browser text-to-speech
- FR-8: Questions are displayed on screen as text simultaneously
- FR-9: User can navigate to the next question after reviewing feedback

### Voice Input
- FR-10: User presses a button to start/stop recording their answer
- FR-11: App transcribes spoken answer to text using browser speech recognition
- FR-12: Transcribed text is displayed on screen so the user can see what was heard
- FR-13: User can skip a question (counts as incorrect, score of 0.0)

### AI Grading
- FR-14: Transcribed answer is sent to the Claude API along with the question and expected answer
- FR-15: LLM returns a judgment (correct / partially correct / incorrect)
- FR-16: LLM returns an explanation that states what the user got right and what was missing
- FR-17: The correct/expected answer is shown after grading

### Session Tracking
- FR-18: Session is one randomized pass through all generated questions
- FR-19: App tracks score as points: 1.0 (correct), 0.5 (partially correct), 0.0 (incorrect/skipped)
- FR-20: Score summary is displayed on screen throughout the session (e.g., "4.5 / 6 points")
- FR-21: User can end the session early via an "End Quiz" button
- FR-22: A summary screen is shown at the end of the session with final score and per-question results

### UI Feedback
- FR-23: A loading indicator is shown during file upload and question generation
- FR-24: Errors are displayed to the user (file extraction failure, API failure, speech recognition failure)

---

## Non-Functional Requirements

- NFR-1: Frontend communicates with the FastAPI backend via REST endpoints
- NFR-2: Claude API key is stored server-side (not exposed to the browser)
- NFR-3: Must work in Chrome (primary target for Web Speech API support)
- NFR-4: File uploads limited to PDF and .docx for v1
- NFR-5: Chrome's speech recognition requires an internet connection (audio is sent to Google's servers); the app will not work offline for STT
- NFR-6: Expected answers are included in the question objects sent to the frontend; users can inspect them via browser DevTools (acceptable tradeoff for a personal study tool)

## API Endpoints

| Method | Route              | Purpose                                  |
|--------|--------------------|------------------------------------------|
| GET    | `/health`          | Server health check                      |
| POST   | `/upload`          | Accept a file, extract text, return questions |
| POST   | `/grade`           | Accept question + answer, return judgment |

### `POST /upload`
- Accepts: multipart file (PDF or .docx)
- Returns: JSON array of question objects
- Note: This is a synchronous call that may take 10-30 seconds due to the Claude API call; the frontend must show a loading state and set an appropriate timeout

### `POST /grade`
- Accepts:
  ```json
  {
    "question": "What is...",
    "expected_answer": "The expected response",
    "user_answer": "What the user said"
  }
  ```
- Returns:
  ```json
  {
    "judgment": "partially_correct",
    "score": 0.5,
    "explanation": "You correctly identified X, but missed Y."
  }
  ```
- `judgment` is one of: `correct`, `partially_correct`, `incorrect`
- `score` is: 1.0, 0.5, or 0.0 respectively

---

## Question Bank Format
- Questions stored as a JSON array
- Each question has:
  - `question` — the text read aloud / displayed
  - `expected_answer` — reference answer for the LLM grader
- Optional fields (generated by Claude but not used in v1 UI):
  - `topic` — category tag for filtering (reserved for v2)
  - `difficulty` — easy / medium / hard (reserved for v2)

---

## Out of Scope (v1)
- Automatic question generation from a GitHub repo
- User accounts or persistent storage across sessions
- Support for browsers other than Chrome
- Multiple choice or non-voice answer modes
- Hosting / deployment (runs locally for now)
- Custom voice selection or speech rate settings
- File types beyond PDF and .docx
- Retry / re-queuing of missed or partial questions (deferred to v1.1)
- Configurable question count

---

## Resolved Decisions
1. **Partial credit:** Yes — partially correct answers earn 0.5 points. The grading
   explanation must tell the user what was right and what was missing.
2. **Retry:** Deferred to v1.1. In v1, each question is asked once. Missed or partially
   correct questions appear in the end-of-session summary but do not re-enter the pool.
3. **Question order:** Randomized each session.
4. **Session state:** Lives entirely in the frontend (JavaScript). The backend is
   stateless. Refreshing the page loses the current session. This is acceptable for v1.
5. **Score model:** Points-based. 1.0 (correct), 0.5 (partial), 0.0 (incorrect/skipped).
   Displayed as "X / Y points" throughout the session.
